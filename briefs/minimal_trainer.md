# Brief: a minimal Hugging Face + PyTorch trainer for the exact confidence objective

You are working in a checkout of github.com/rrenaud/rewarding_doubt (the main clone is
`/home/rrenaud/rewarding_doubt`; you may be in a git worktree of it on its own branch). Read
`README.md` and `docs/fast_loop_log.md` first; the log is the record of the fast loop this
replaces and of every number quoted below.

## Goal

Write `modal_repro/minimal_trainer.py`: one self-contained file (aim for 300–400 lines) that trains
Qwen-2.5-3B to state a calibrated confidence with the exact objective, using only Hugging Face
`transformers`, `peft` (optional) and PyTorch: **no Unsloth, no TRL, no imports from the released
RewardingDoubt code**. We are willing to diverge from the released repo for speed and simplicity;
reported numbers will still be checked with the released evaluation separately.

Why: the current trainers (`modal_repro/fast_loop.py`, `modal_repro/exact_llama.py`) run through
Unsloth, which cost us repeatedly (`docs/fast_loop_log.md` sections 2, 7, 8): forced gradient
checkpointing (re-enabled by `FastLanguageModel.for_training`), every layer's input forced to
require grad, attention internals (`causal_mask`, `_has_no_labels`) needed to read hidden states,
a decoding loop that bypasses modules, and no way to reuse a cached prompt prefix. TRL's
PPOTrainer is unused by the exact objective.

## What to build, in order

1. **Cached mode first** (replaces `fast_loop.py train`). Same data, objective, schedule, metrics:
   - Model: `Qwen/Qwen2.5-3B-Instruct` (or `unsloth/Qwen2.5-3B-Instruct`, same weights) in **bf16**,
     not 4-bit; attention via PyTorch SDPA. Gradient checkpointing off.
   - Adapters: (a) LoRA r=8, alpha=8, dropout 0, no bias, on q,k,v,o,gate,up,down (PEFT is fine),
     with `--lora-modules` / `--lora-layers` like fast_loop; (b) bias vectors added to attention
     outputs and/or MLP outputs of chosen layers (`--attn-bias A-B`, `--residual-bias A-B`) via
     ordinary forward hooks; zero-initialized.
   - Scoring: the 11 confidence levels from one forward pass, logits only at the read positions.
     Reuse `modal_repro/shared_prefix.py: LevelScheme` (Qwen splits numbers into digits: "10" is
     "1" "0"; `LevelScheme` handles it) or reimplement `fast_loop.level_logps` with plain HF:
     run `model.model(...)` for hidden states, apply `lm_head` at the needed positions only.
   - **Shared-prefix reuse (the main speed lever):** 132 of the ~164 tokens per training row are a
     prompt prefix identical across rows. Compute it once per minibatch with `use_cache=True`
     (with grad, since adapters change it), expand the KV cache over the batch, run only the
     suffixes. Verify against a full forward (max abs difference of level log-probs < 1e-2 in bf16).
   - Objective: `rewarding_doubt.core.baseline_matched_objective(levels.double(), label,
     "discrete-exact", "released", -30.0, ref_logq=ref.double())` per row, loss = -(J - beta * KL),
     as in `fast_loop.train`. Fixed beta 0.05 default; `--adaptive-kl` with
     `rewarding_doubt.paper_ppo.AdaptiveKLController(0.05, 6, 10000)` optional.
   - Schedule defaults (the fast loop's): one Adam update per 32 length-bucketed questions, lr 3e-4,
     300 steps, dev evaluation every 50 steps; copy `fast_loop.epoch_batches` for bucketing.
   - Dev metrics: copy `fast_loop.dev_metrics_from_levels` (expected-confidence Brier / ECE /
     AUROC via `rewarding_doubt.paper_ppo.evaluation_metrics`, plus a T=0.6 sampled confidence).
   - Logging: `metrics.jsonl` per step (reward, KL, mean confidence, seconds, optional per-phase
     timing) and `curve.json` {step: dev metrics}, like fast_loop.

2. **Online mode** (answers regenerated by the policy, for later): every N steps, generate answers
   with `model.generate` (released prompt, T=0.6, top-p 0.9, stop at " Confidence"), grade them,
   and train on those rows. Optional; do it only after cached mode is validated.

## Data

The rollout cache is on the Modal volume `rewarding-doubt-repro` at `/vol/fast/qwen25-3b-cache.pt`
(6.5 MB; `modal volume get rewarding-doubt-repro fast/qwen25-3b-cache.pt <local>` to inspect):
`{"model", "created", "splits": {"train": [8000 rows], "dev": [507 rows]}}`, each row
`{"ids": prompt + answer tokens ending in " Confidence", "qid", "answer", "f1": bool, "em": bool,
"ref": [11] float tensor}`. Training labels are `em` (released default), dev labels `f1`.

**`ref` was computed by the 4-bit Unsloth model.** With a bf16 model the KL at step 0 would not
be ~0. Recompute `ref` once with the new model (adapter off), cache it next to the original
(e.g. `/vol/fast/qwen25-3b-cache-bf16ref.pt`), and report the untrained dev metrics of the bf16 model
(the 4-bit one: Brier 0.566, ECE 0.573, AUROC 0.787 on these 507 rows).

## Running

GPU work goes on Modal (`modal_repro/app.py`, app `rewarding-doubt-repro`, volume mounted at
`/vol`). Add the new file to the image (`.add_local_file(... "minimal_trainer.py" ...)`, as for
`fast_loop.py`) and an entrypoint modelled on `fast_train` (configs JSON {label: [args]}, runs in
parallel, results copied to `runs/minimal/<label>/`). Use `modal run --detach` for anything long:
the local client's login has expired mid-run before. The local machine has only a 4 GB GPU; use the
`pytorch-cuda` conda env for local CPU/GPU tests if needed. If the Modal image's pinned
`transformers` (from the released requirements) is too old for something, say so before changing
pins; a separate lighter image for this trainer is acceptable.

## Validation (required before calling it done)

1. Untrained bf16 model on the 507 dev rows: report Brier / ECE / AUROC (expected near the 4-bit
   numbers, not identical).
2. Shared-prefix scoring equals full-forward scoring (state the max difference).
3. Full LoRA, Adam 3e-4, batch 32, 300 steps, 3 seeds: the fast loop got dev Brier 0.120 ± 0.004,
   AUROC 0.915 ± 0.005, ECE 0.040 ± 0.014 at step 300 (Brier 0.116 / AUROC 0.907 at step 150).
4. Attention-output bias, layers 18–35, lr 1e-2, 2 seeds: the fast loop got Brier 0.114 ± 0.002,
   AUROC 0.908 ± 0.001 at step 300.
5. Time per step (32 questions) with `--time-steps`-style phase timing, against the fast loop's
   611 ms (all-layer LoRA, Unsloth, checkpointing off) and 442 ms (layers 18–35 with backward cut).

Matching within seed noise is the bar. Training is not bitwise reproducible on GPU; compare means
over seeds. If something does not match, find out why before tuning anything.
