## Exact expected-reward objective for the confidence (`--objective exact`)

**Opt-in only.** The default `--objective ppo` behaves exactly as before.

### What it does

After an answer, the confidence is one of eleven strings `": 0"` … `": 10"`, so its expected reward can be computed exactly instead of estimated from one sampled response:

```
J  = Σ_k p(k)·R(k) + (1 − Σ_k p(k))·wrong_format_penalty
KL = KL(p ‖ p_ref) over the 11 levels + "anything else"
loss = −(J − β·KL)
```

- **Unchanged:**
  - `R(k)` is the existing `QAResult_to_reward` for confidence `k`.
  - `p_ref` is the policy with the LoRA adapter disabled, the same reference TRL uses for PEFT models.
  - `β` comes from the PPO trainer's existing adaptive KL controller.
  - Optimizer, LoRA, data, prompt and evaluation are untouched.
  - Updates follow PPO's schedule (`ppo_epochs` × minibatches).
- **Removed for this objective:** sampling a confidence (the second `generate`), the value head, advantage estimation and ratio clipping.

`--objective exact` reads all eleven level probabilities from one forward pass over `prefix + ": "`, one softmax. When `"10"` is two tokens (Qwen-2.5), it appends `"1"` to get P("0" | "1"). Its one approximation: a level's probability leaves out the end-of-turn token after the number.

`--objective exact_reference` scores the eleven complete strings `": k<eot>"` as separate sequences. It's the same objective without that approximation, about 5× slower, and useful for checking. On both Llama-3-8B and Qwen-2.5-3B, the fast path's level probabilities match token-by-token scoring (max difference 6e-8; exactly 0 on Llama).

The PR also lets the code run on Qwen-2.5: the three `<|eot_id|>` lookups fall back to the tokenizer's end-of-turn token when `<|eot_id|>` doesn't exist. On Llama-3 it's the same token as before.

- `SingleAnswerSetting/util/ExactConfidence.py` (new)

### Results

All with this repository's settings: learning rate 1e-5, batch 8, adaptive KL (init 0.05, target 6), and the default reward grading. Scored with `InferenceDatasetSplit` and the existing metrics (F1 > 0.5, 11-bin ECE).

**Qwen-2.5-3B, full TriviaQA training set, 3,000 steps**, 512 questions from the TriviaQA validation split, mean over snapshots at steps 1,000–3,000 (one seed per arm):

| `--objective` | ECE ↓ | AUROC ↑ | Brier ↓ |
|---|---:|---:|---:|
| `exact` | **0.035** | **0.894** | **0.127** |
| `ppo` (default) | 0.106 | 0.864 | 0.148 |

**KL settings.** PPO is not limited by the KL constraint. Same setup, mean over the five snapshots at steps 1,000–3,000 (ECE / AUROC):

| KL setting | `ppo` | `exact` |
|---|---|---|
| adaptive, target 6 (default) | 0.106 / 0.864 | **0.035 / 0.894** |
| adaptive, target 20 | 0.128 / 0.848 | 0.051 / 0.863 |
| fixed 0.05 | 0.162 / 0.817 | 0.055 / 0.883 |
| none | 0.114 / 0.849 | 0.071 / 0.872 |

**Seeds, at a smaller scale.** Qwen-2.5-3B, 1,024 training questions, 256 steps, 512 test questions, mean ± sd over 3 seeds:

| `--objective` | ECE ↓ | AUROC ↑ | Brier ↓ | Time per iteration (L40S) |
|---|---:|---:|---:|---:|
| `exact` | 0.056 ± 0.021 | 0.803 ± 0.005 | 0.172 ± 0.001 | 2.3 s |
| `exact_reference` | 0.088 ± 0.014 | 0.800 ± 0.006 | 0.179 ± 0.004 | 11.2 s |
| `ppo` (default) | 0.257 ± 0.018 | 0.781 ± 0.018 | 0.257 ± 0.015 | 15.1 s |

**Baseline check.** Untrained Qwen-2.5-3B in this setup: ECE 0.525, AUROC 0.62, accuracy 41.8%. The paper's Table 3 reports 0.533 / 0.598 / 41.9%.

### Limitations

- **Single seeds on the long runs, and a 512-question evaluation set.** ECE can't resolve below about 0.04 at that size.
- **Very long training with the adaptive controller degrades `exact`.** On a 21,900-step run (stopped near step 16,000), dev ECE went from 0.032 at step 1,000 to 0.108 at 8,000 and 0.222 at 15,000. The controller kept raising β to hold KL at 6 nats, which pulls the confidence back toward the base model's near-constant "10". With a fixed β of 0.05, ECE stayed at 0.04–0.05 through step 2,500.
- **Answers are generated by the training policy, as before,** so long training can change them.

### Notes found while reproducing

- `QAResult_to_reward` grades answers by exact match by default, while the paper describes F1 > 0.5.
- TRL's `PPOTrainer` calls `set_seed(config.seed)`, so runs that differ only in a manual seed can come out identical unless `PPOConfig.seed` is set.

### Running it

```
python Train.py --objective exact --dataset triviaqa --is_unsloth \
  --model_dir unsloth/Qwen2.5-3B-Instruct --tokenizer_dir unsloth/Qwen2.5-3B-Instruct \
  --epochs 2 --lr 1e-5 --batchsize 8
```
