# Exact confidence rewards for *Rewarding Doubt*

[Rewarding Doubt](https://github.com/pasta99/RewardingDoubt) (ICLR 2026) trains a language model to state a calibrated confidence after each answer: it writes `Answer: …, Confidence: k` with k from 0 to 10, and PPO rewards the stated confidence with a log score.

This repository reproduces that recipe and replaces PPO's sampled policy gradient with an **exact** one. Because the confidence is one of eleven short strings, its expected reward can be computed from a single forward pass:

```
J = Σ_k p(k)·R(k) + (1 − Σ_k p(k))·(−30)
```

Here R(k) is the paper's reward for stating k and −30 its penalty for a malformed confidence. The KL term to the base model, the adaptive KL controller, the optimizer and the data are the paper's. No confidence is sampled and no value head is needed.

The change is available as an opt-in flag for the released code: [pasta99/RewardingDoubt#2](https://github.com/pasta99/RewardingDoubt/pull/2) ([`patches/exact_confidence.patch`](patches/exact_confidence.patch)).

## Results

**Qwen-2.5-3B, the released code and settings with only the patch applied, full TriviaQA training set, 3,000 steps.** Scored with the released evaluation on 512 questions from the TriviaQA validation split. Each cell is the mean over the snapshots at steps 1,000–3,000 (one seed per arm):

| `--objective` | ECE ↓ | AUROC ↑ | Brier ↓ |
|---|---:|---:|---:|
| `exact` | **0.035** | **0.894** | **0.127** |
| `ppo` (released default) | 0.106 | 0.864 | 0.148 |

- **PPO is not limited by its KL constraint.** Across four KL settings (adaptive target 6 or 20, fixed 0.05, none), the released default is PPO's best, and `exact` is ahead at every setting.
- **The gap holds over seeds at a smaller scale** (1,024 training questions, 256 steps, 3 seeds each): ECE 0.056 ± 0.021 for `exact` vs 0.257 ± 0.018 for `ppo`.
- **It is faster:** 2.3 s vs 15.1 s per training iteration on an L40S.
- **The base model reproduces the paper's Table 3** (untrained Qwen-2.5-3B: ECE 0.525, AUROC 0.62, accuracy 41.8%; paper 0.533, 0.598, 41.9%).
- **Llama-3-8B, our own trainer, full training set:** dev ECE 0.038 for exact + KL at 4,000 steps (2 seeds) vs 0.150 for PPO + KL at 3,500 steps (1 seed; the other ran out of memory). See [`docs/long_runs.html`](docs/long_runs.html).

**Limitations.**
- The long runs use one seed per arm, and a 512-question evaluation cannot resolve ECE below about 0.04.
- Over very long training (8,000+ steps), the paper's adaptive KL controller pulls `exact`'s confidence back toward the base model's near-constant "10", and dev ECE rises to 0.22 by step 15,000. A fixed KL weight avoids this.
- Answers are generated by the policy being trained, as in the paper, so long training can change them; `--frozen-answers` in our trainers generates them with the adapter off instead.

## Running

The Modal app builds an image with the released code at commit `416c9e0`, its pinned requirements and the patch:

```bash
pip install -e .            # src/rewarding_doubt
pytest tests                # CPU only
modal run modal_repro/app.py::minimal_diff --objectives exact,ppo   # Qwen-2.5-3B, 3 seeds each
```

Long runs go to RunPod with the image `ghcr.io/rrenaud/rewarding-doubt`; see [`runpod/README.md`](runpod/README.md). For the released code with the patch alone:

```bash
git clone https://github.com/pasta99/RewardingDoubt && cd RewardingDoubt
git checkout 416c9e0 && git apply ../patches/exact_confidence.patch
cd SingleAnswerSetting
python Train.py --objective exact --dataset triviaqa --is_unsloth \
  --model_dir unsloth/Qwen2.5-3B-Instruct --tokenizer_dir unsloth/Qwen2.5-3B-Instruct \
  --epochs 2 --lr 1e-5 --batchsize 8
```

Infrastructure names (the Modal volume, RunPod network volume, W&B project) are this project's own; change them in `modal_repro/app.py`, `scripts/runpod_launch.py` and `runpod/` to run elsewhere.
