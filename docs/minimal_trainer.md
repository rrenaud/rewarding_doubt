# A minimal trainer for the exact objective

October 6, 2026 (times PST). Qwen-2.5-3B, exact objective, cached rollouts, `modal_repro/minimal_trainer.py`.
Every run is on one L40S on Modal; per-run outputs (`train.log`, `metrics.jsonl`, `curve.json`) and the config
files that launched them are in `runs/minimal/`.

**Outcome.** One file of 400 lines with Hugging Face `transformers`, PEFT and PyTorch only (no Unsloth, no
TRL) reproduces the fast loop (`docs/fast_loop_log.md`) within seed noise and is faster: 489 ms per step for
all-layer LoRA in bf16 against the fast loop's 611, and 302 against 442 for layers 18–35. The speed comes from
running the 132-token prompt prefix once per minibatch. With the fast loop's own 4-bit weights it trains too,
21–53% slower than in bf16; with fp32 LoRA weights (PEFT's default) 2 of 6 seeds collapsed for a while, which
the fast loop's bf16 LoRA weights did not do in 6 seeds.

## What it does

- **Model**: `Qwen/Qwen2.5-3B-Instruct` weights in bf16 (`unsloth/Qwen2.5-3B-Instruct`, as cached), PyTorch SDPA
  attention, no gradient checkpointing. `--model unsloth/Qwen2.5-3B-Instruct-bnb-4bit` loads the pre-quantized
  checkpoint Unsloth itself loads for `load_in_4bit` (bitsandbytes NF4, double quantization).
- **Adapters**: PEFT LoRA (r 8, alpha 8, no dropout) only on the chosen modules and layers (`--lora-modules`,
  `--lora-layers`); zero-initialized vectors added to attention or MLP outputs by forward hooks (`--attn-bias`,
  `--residual-bias`). Inputs never require grad, so backward stops at the first trained layer by itself: none
  of fast loop's `cut_backward_below`, `set_gradient_checkpointing` or `causal_mask` workarounds.
- **Scoring**: logits only at the read positions (`Levels`, a re-implementation of `LevelScheme` for one-token
  and Qwen's digit-split "10"); the prompt prefix shared by the minibatch runs once (batch 1, with grad), its
  key/value cache is expanded over the batch, and only the suffixes (~25–140 tokens) run.
- **Objective, schedule, dev metrics, logging**: fast loop's, copied (`baseline_matched_objective` per row,
  fixed β 0.05 or `--adaptive-kl`, Adam 3e-4, batches of 32 length-bucketed questions, 300 steps, dev every 50).
- **Not carried over**: gate biases (`--gate-bias`), the released schedule's minibatch flags are kept but
  untested here, cache building (`fast_loop.py cache` still builds the cache), and online mode (answers
  regenerated by the policy), which the brief made optional and which is not written.

## 1. Reference levels in bf16

The cache's reference levels were computed by the 4-bit model. On 64 dev rows they differ from the bf16
model's by up to 10.4 nats (7.8 on levels with q > 1e-3; expected confidence by up to 3.1 levels), so
`minimal_trainer.py ref` recomputed them (26 s for 8,507 rows) into `/vol/fast/qwen25-3b-cache-bf16ref.pt`.

| untrained model, 507 dev rows | Brier | ECE | AUROC |
|---|---:|---:|---:|
| bf16 (this trainer) | 0.516 | 0.539 | 0.816 |
| 4-bit through plain HF (this trainer, `--model ...-bnb-4bit`) | 0.566 | 0.573 | 0.785 |
| 4-bit through Unsloth (fast loop) | 0.566 | 0.573 | 0.787 |

The bf16 model is less overconfident (mean training-row confidence 9.54 against 9.89). Plain HF reproduces
Unsloth's 4-bit model to three decimals on Brier and ECE.

## 2. Shared prefix against a full forward

`minimal_trainer.py diagnose` (`runs/minimal/diagnose/`), 64 dev rows, max |difference| of the level log-probs:

| comparison | bf16 | fp32 |
|---|---:|---:|
| shared prefix vs full forward | 1.88 | **0.0032** |
| full forward, batch of 64 vs one row at a time | 1.23 | 0.0027 |
| shared prefix vs one row at a time | 1.90 | 0.0032 |

In fp32 the shared prefix matches a full forward as closely as two batchings of the full forward match each
other. The brief's bar (< 1e-2 in bf16) cannot be met by any bf16 scoring: the same full forward with a
different batch composition already moves some rows' levels by 1.2 nats (expected confidence by up to 0.43).
That noise was there in the fast loop too. The CPU test (`tests/test_minimal_trainer.py`, tiny random Qwen2
with LoRA and both biases) checks levels and gradients: 2e-6 and 2e-7 relative in fp32.

KL at step 1, between the policy and a reference scored with a different batching: 0.006 (bf16), 0.0066
(4-bit through HF against Unsloth's reference), 0.0044 in the fast loop.

Defaults: fixed β 0.05, Adam 3e-4, batches of 32, 300 steps. Mean ± sd over seeds, expected-confidence metrics.

| run | seeds | Brier @150 | AUROC @150 | Brier @300 | ECE @300 | AUROC @300 | time |
|---|---:|---|---|---|---|---|---:|
| all-layer LoRA, minimal (bf16) | 3 | 0.133 ± 0.038 | 0.900 ± 0.030 | **0.112 ± 0.017** | 0.039 ± 0.007 | **0.918 ± 0.014** | 2.9 min |
| all-layer LoRA, fast loop | 3 | 0.116 ± 0.006 | 0.907 ± 0.007 | 0.120 ± 0.004 | 0.040 ± 0.014 | 0.915 ± 0.005 | 3.5 min |
| attention bias 18–35, lr 1e-2, minimal (bf16) | 2 | 0.153 ± 0.038 | 0.900 ± 0.001 | 0.122 ± 0.008 | 0.065 ± 0.034 | 0.914 ± 0.006 | 1.1 min |
| attention bias 18–35, lr 1e-2, fast loop | 2 | 0.147 ± 0.034 | 0.891 ± 0.008 | 0.114 ± 0.002 | 0.050 ± 0.022 | 0.908 ± 0.001 | 2.7 min |

Within seed noise at step 300 on every metric. The spread at step 150 is seed 3's dip (0.176 / 0.865, back
to 0.142 / 0.918 at step 200), the kind of hard-batch spike the fast loop log notes around step 200. Times
run from the first update to the end, including 6 dev evaluations, excluding model loading. The base models differ (bf16 here, 4-bit there), so this is a
comparison of recipes, not a reproduction; section 5 runs the same weights.

## 4. Time and memory

`--time-steps`, 60-step runs, mean over steps 11–60, ms per step of 32 questions (`runs/minimal/*timing-*`):

| run | forward | loss | backward | optimizer | ms / step | fast loop |
|---|---:|---:|---:|---:|---:|---:|
| all-layer LoRA, bf16 | 189 | 29 | 264 | 7 | **489** | 611 |
| all-layer LoRA, bf16, no shared prefix | – | – | – | – | out of memory | |
| LoRA 18–35, bf16 | 136 | 24 | 138 | 4 | **302** | 442 (with the cut) |
| LoRA 18–35, bf16, no shared prefix | 334 | 14 | 326 | 3 | 676 | |
| attention bias 18–35, bf16 | 85 | 20 | 65 | 1 | **172** | |
| all-layer LoRA, 4-bit | 286 | 31 | 336 | 9 | 663 | 611 |
| LoRA 18–35, 4-bit | 190 | 22 | 149 | 4 | 365 | 442 (with the cut) |
| attention bias 18–35, 4-bit | 146 | 22 | 93 | 1 | 263 | |

- **The shared prefix halves a step** (676 → 302 ms for layers 18–35); it is the main gain over the fast loop.
- **4-bit costs 21–53% over bf16** (bitsandbytes dequantizes every weight in every matmul, forward and in the
  backward through trained layers). It costs most where the rest of the step is cheapest (biases only).
  Against Unsloth's 4-bit kernels: 9% slower for all-layer LoRA, 17% faster for layers 18–35.
- **The loss is 20–30 ms**: 32 calls of `baseline_matched_objective`. Not optimized.

Memory, one bucketed batch of 32 rows of 156–157 tokens, all-layer LoRA (`minimal_trainer.py memory`,
`runs/minimal/memory/`):

| model | weights | peak, shared prefix | peak, full rows |
|---|---:|---:|---:|
| bf16 | 5.9 GB | 14.1 GB | 39.3 GB |
| 4-bit | 2.0 GB | 10.1 GB | 35.4 GB |

Activations take about 200 KB per token per layer: bf16 MLP intermediates (4 × 11,008 values) and PEFT's fp32
copies of every LoRA input (about 45%). The fast loop's peak at full length was 16 GB, thanks to Unsloth's
fused kernels. Over a training run the peak is 33 GB (4-bit, fp32 adapters; 23.6 GB with bf16 adapters),
set by the longest bucketed batches (rows up to 271 tokens). All-layer LoRA on full rows does not fit in
48 GB at minibatch 32; a 24 GB GPU needs bf16 adapters or a smaller minibatch.

## 5. The same 4-bit weights: LoRA weight precision

With the fast loop's 4-bit weights and its original cache (4-bit reference), all-layer LoRA, default schedule:

| LoRA weights | seeds | Brier @150 | AUROC @150 | Brier @300 | ECE @300 | AUROC @300 | collapsed |
|---|---:|---|---|---|---|---|---:|
| fp32 (PEFT default) | 6 | 0.160 ± 0.081 | 0.834 ± 0.189 | 0.146 ± 0.051 | 0.062 ± 0.021 | 0.895 ± 0.023 | 2 of 6 |
| bf16 (`--adapter-dtype bfloat16`, as the fast loop) | 3 | 0.127 ± 0.018 | 0.903 ± 0.013 | 0.124 ± 0.019 | 0.053 ± 0.027 | 0.901 ± 0.012 | 0 of 3 |
| fast loop (Unsloth, bf16 LoRA weights) | 3 | 0.116 ± 0.006 | 0.907 ± 0.007 | 0.120 ± 0.004 | 0.040 ± 0.014 | 0.915 ± 0.005 | 0 of 3 |

"Collapsed": Brier 0.322 with AUROC near 0.5, one confidence for every answer. Seed 3 with fp32 weights
collapsed from step 100 to 200 and ended at 0.246 / 0.855; seed 2 collapsed at step 200 and recovered by 300
(0.124 / 0.906). The other four fp32 seeds give 0.126 ± 0.016 / 0.902 ± 0.015 at step 300.

The fast loop calls TRL's `peft_module_casting_to_bf16`, which casts every LoRA layer to bf16, so Adam's
updates were rounded to bf16 weights; PEFT keeps them in fp32. Batch order depends only on the seed, and the
two collapsing seeds did not collapse with bf16 weights. That is consistent with fp32 weights taking larger
effective steps at lr 3e-4, already near the edge (1e-3 collapses 2 of 3 seeds in the fast loop), but 2 of 6
against 0 of 6 is not significant (Fisher exact p ≈ 0.45). In bf16 (section 3), fp32 weights had no
collapse in 3 seeds. Not yet run: fp32 weights at a lower learning rate, and more seeds.

## Reproducing

```bash
modal run modal_repro/app.py::minimal_ref                       # bf16 reference cache + untrained metrics
modal run modal_repro/app.py::minimal_diagnose                  # section 2
modal run modal_repro/app.py::minimal_memory                    # section 4, memory
modal run --detach modal_repro/app.py::minimal_train --configs runs/minimal/validation_configs.json
modal run --detach modal_repro/app.py::minimal_train --configs runs/minimal/timing_configs.json
modal run --detach modal_repro/app.py::minimal_train --configs runs/minimal/four_bit_configs.json --four-bit
modal run --detach modal_repro/app.py::minimal_train --configs runs/minimal/adapter_dtype_configs.json --four-bit
pytest tests/test_minimal_trainer.py                            # needs transformers 4.48 and peft (the Modal image's pins)
```
